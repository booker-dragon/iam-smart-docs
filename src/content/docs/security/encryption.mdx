On top of HTTPS, every POST body, every response `content` and every callback body is encrypted (spec §2.3). The one exception is [Request CEK](/api/operations/request-cek/) itself.

## The two keys

| Key | What it is | Where it comes from |
| --- | --- | --- |
| **KEK** — key encryption key | The RSA key pair of the encipherment certificate you upload in the Self-Service Portal. | A Hong Kong Recognised Certification Authority. You keep the private key. |
| **CEK** — content encryption key | A 256-bit AES key that encrypts business data. | Generated by iAM Smart, sent to you encrypted with your KEK's public key. |

## Lifecycle

<Steps>

1. Call [Request CEK](/api/operations/request-cek/) (`POST /api/v1/security/getKey`, signed but not encrypted).
2. Decrypt `secretKey` with your KEK private key to get the 32-byte CEK.
3. Cache it until `issueAt + expiresIn`. `expiresIn` can change between calls, so always compute the expiry from both fields.
4. Encrypt request bodies and decrypt response `content` with the CEK.
5. When you get `D30002` (CEK missing or expired) or `D30001` (KEK missing or expired), request a new CEK and retry.

</Steps>

<Aside type="caution" title="Rotating your certificate">
  After you configure a new KEK, *Request CEK* keeps returning the **existing** CEK, still wrapped with the old KEK, until it expires. To switch immediately, call [Revoke CEK](/api/operations/revoke-cek/) and then *Request CEK* again.
</Aside>

## What gets encrypted

| Message | Field | Encrypted? | How |
| --- | --- | --- | --- |
| Your request | body | Yes | `{"content": Base64(AES-GCM(JSON body))}` |
| Your request | headers, URL parameters | No | |
| Response | `txID`, `code`, `message` | No | |
| Response | `content` | Yes | Base64(AES-GCM(JSON content)) |
| Callback to you | `content` | Yes | Base64(AES-GCM(JSON content)) |
| Callback to you | `secretKey` | — | The CEK used for this callback, RSA-encrypted with your KEK, Base64 |

## Ciphertext format

`AES/GCM/NoPadding`, a fresh random **12-byte IV** per message and a 128-bit authentication tag. The Base64 string decodes to:

```txt
Base64( 00 00 00 0C | IV (12 bytes) | ciphertext | GCM tag (16 bytes) )
        └ IV length as a big-endian int32 = 12
```

Never reuse an IV with the same CEK.

<Tabs>
<TabItem label="Node.js">

```js
import crypto from 'node:crypto'

export function encrypt(plaintext, cek) {
  const iv = crypto.randomBytes(12)
  const cipher = crypto.createCipheriv('aes-256-gcm', cek, iv)
  const ct = Buffer.concat([cipher.update(plaintext, 'utf8'), cipher.final()])
  const len = Buffer.alloc(4)
  len.writeInt32BE(iv.length)
  return Buffer.concat([len, iv, ct, cipher.getAuthTag()]).toString('base64')
}

export function decrypt(b64, cek) {
  const data = Buffer.from(b64, 'base64')
  if (data.readInt32BE(0) !== 12) throw new Error('invalid iv length')
  const decipher = crypto.createDecipheriv('aes-256-gcm', cek, data.subarray(4, 16))
  decipher.setAuthTag(data.subarray(data.length - 16))
  return Buffer.concat([decipher.update(data.subarray(16, data.length - 16)), decipher.final()]).toString('utf8')
}
```

<TabItem label="Python">

```python
import base64, os, struct
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

def encrypt(plaintext: bytes, cek: bytes) -> str:
    iv = os.urandom(12)
    return base64.b64encode(struct.pack(">i", 12) + iv + AESGCM(cek).encrypt(iv, plaintext, None)).decode()

def decrypt(b64: str, cek: bytes) -> bytes:
    data = base64.b64decode(b64)
    if struct.unpack(">i", data[:4])[0] != 12:
        raise ValueError("invalid iv length")
    return AESGCM(cek).decrypt(data[4:16], data[16:], None)
```

<TabItem label="Java (from the spec)">

```java
private static final String AES_GCM_NOPADDING = "AES/GCM/NoPadding";

public static String encrypt(byte[] contentByte, byte[] key) {
    SecretKeySpec skeySpec = new SecretKeySpec(key, "AES");
    SecureRandom secureRandom = new SecureRandom();
    byte[] iv = new byte[12];            // do not reuse iv with the same key
    secureRandom.nextBytes(iv);
    Cipher cipher = Cipher.getInstance(AES_GCM_NOPADDING);
    cipher.init(Cipher.ENCRYPT_MODE, skeySpec, new GCMParameterSpec(128, iv));
    byte[] encrypted = cipher.doFinal(contentByte);
    ByteBuffer byteBuffer = ByteBuffer.allocate(4 + iv.length + encrypted.length);
    byteBuffer.putInt(iv.length);
    byteBuffer.put(iv);
    byteBuffer.put(encrypted);
    return Base64Util.base64Encode(byteBuffer.array());
}

public static String decrypt(byte[] content, byte[] key) {
    SecretKeySpec skeySpec = new SecretKeySpec(key, "AES");
    ByteBuffer byteBuffer = ByteBuffer.wrap(content);
    int ivLength = byteBuffer.getInt();
    if (ivLength != 12) throw new IllegalArgumentException("invalid iv length");
    byte[] iv = new byte[ivLength];
    byteBuffer.get(iv);
    byte[] cipherText = new byte[byteBuffer.remaining()];
    byteBuffer.get(cipherText);
    Cipher cipher = Cipher.getInstance(AES_GCM_NOPADDING);
    cipher.init(Cipher.DECRYPT_MODE, skeySpec, new GCMParameterSpec(128, iv));
    return new String(cipher.doFinal(cipherText));
}
```

Exception handling from the spec's listing is omitted for brevity.

## Unwrapping the CEK

The spec says iAM Smart uses “the RSA algorithm” with your KEK to encrypt the CEK, without naming the padding. Java's `Cipher.getInstance("RSA")` defaults to PKCS#1 v1.5, which is the likeliest choice, but confirm with the support team. The reference clients and the tool below try PKCS#1 v1.5 first and fall back to OAEP.

<Aside type="note" title="Node.js and PKCS#1 v1.5">
  Node.js 20+ refuses `RSA_PKCS1_PADDING` for private-key decryption (CVE-2023-46809). The [reference client](/guides/client/) decrypts with `RSA_NO_PADDING` and removes the PKCS#1 v1.5 padding itself.
</Aside>

## Handle these cases

- Retry *Request CEK* when you receive an encryption/decryption error code, then decrypt with the newest CEK (§2.3.2).
- Store the CEK instead of requesting it per call — frequent calls can get HTTP **429**.
- Prepare a fallback for when the iAM Smart API is unavailable.
